| <a href="https://github.com/hugocorreia123/prism-token-taxes" target="_blank" rel="noopener noreferrer"><b>🔺 Prism — The Token Taxes</b></a><br><img src="https://img.shields.io/badge/954_runs-pre--registered-4F46E5?style=flat" alt="954 runs, pre-registered"/> | **Do the popular ways of cutting LLM token spend actually save money?** Measured against *all-in tokens per **successful** task* — the number that decides the bill, since a failed run costs full price. On a **3B model the three techniques applied together roughly doubled the cost per completed task**: accuracy fell 31.3% → 16.2%, so the savings were swamped by paying for twice as many failures. On a **70B model the same interventions cost no accuracy at all** (92.3% → 91.7%) — and a matched-task control rules out task difficulty: restricted to the identical seven tasks, the 3B model does **worse**, not better. Reported at the strength the intervals support: the penalty demonstrably *disappears* with scale; a saving *appearing* is not claimed. Pre-registered 2×2×2 factorial with a non-inferiority gate and a full audit trail — including a boolean-inversion bug that would have flipped every accuracy conclusion, caught by a synthetic-recovery test before it reached one. <a href="https://github.com/hugocorreia123/prism-token-taxes/blob/main/FINDINGS.md" target="_blank" rel="noopener noreferrer"><b>Findings paper</b></a>. | MLX (local Qwen2.5-3B) · Groq (Llama-3.3-70B) · statsmodels GLM · cluster bootstrap + BCa · TOST · BFCL-v4 · GSM8K |

### 🧭 How I build

One discipline runs through all of it:

- **An honest baseline first.** A deep model that can't beat tuned gradient boosting hasn't earned its complexity — and on one benchmark, mine didn't.
- **Deterministic code where consequence lives.** No court accepts *"the model estimated the 14th."*
- **Measured findings, including the negative ones.** A single-run "win" that turned out to be test-set variance; an LLM judge I disproved four separate ways; a confidence signal I had to report as *unmeasurable*.
- **A human in the loop by measured necessity** — placed where the error rate says, not where the marketing does.
- **Demos a non-technical reviewer can actually use.** Every live app opens with a plain-language tour, gives each metric a one-sentence "what this means", and states its own limitations in the interface — the honesty box is part of the product, not a footnote.
